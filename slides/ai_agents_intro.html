先從熟悉的聊天 AI 開始

聊天 AI 通常回答問題；Agent 以「完成任務」為導向。

例如「說明如何規劃旅行」偏向問答；「依需求蒐集資訊並整理行程」可能涉及多步驟與工具。

示意例子，不代表所有聊天 AI 都沒有工具。

Agent 的核心概念

模型 + 指示 + 工具 + 執行流程

模型理解目標、選擇行動；工具接觸外部資料或服務；執行流程控制各步驟。

重點：不是多加幾個提示詞就一定變 Agent。

三個組件各做什麼？

模型參與判斷；工具執行操作；協調機制管理流程

模型可依任務與工具回傳結果，動態選擇下一步；工具負責查詢或執行操作；協調機制負責工具路由、狀態與權限控管。

🧠
模型理解與推理
🔧
工具查詢與執行
🧭
協調路由與控管
教學簡化：模型與協調機制可能共同影響執行路徑，並非完全固定的職責切割。

Agent 怎麼循環？

目標 → 選擇工具 → 執行 → 觀察 → 再決定

每次取得工具結果後，模型可繼續處理，直到完成任務或觸發停止條件。

🎯
任務接收目標
🛠️
工具獲取資訊
👀
觀察回傳結果
🔁
再決定結束或繼續
來源描述的是典型工具循環；具體停止方式需按系統設定。

Workflow 和 Agent 不一樣

Workflow 固定路線；Agent 可以動態決策

Workflow：先定義 A→B→C。Agent：根據當前資訊判斷下一個工具或步驟。

📋
Workflow預先安排流程
🤖
Agent依情境動態選擇
需要可預測流程時，Workflow 往往更容易控管。

記憶與規劃：不是每個 Agent 都一樣

記憶保存脈絡；規劃拆解多步驟任務

短期記憶保存會話狀態，長期記憶需額外設計。示意：規劃校園講座時，先拆成查場地、排議程；若場地額滿，根據新資訊改選日期並重新規劃。

任務拆解與重新規劃屬教學示意；記憶與規劃不是每個 Agent 都必備。

使用工具也有風險

權限、錯誤資料與不可逆操作要注意

代理可能讀到錯誤資訊；若能操作外部服務，應明確限制權限、檢查結果與保留人工確認。

例：付款、刪除資料等高影響行為應另設審核。
